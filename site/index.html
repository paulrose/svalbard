svalbard

A command-line tool for backing up PostgreSQL and MySQL to S3, R2, or a server over SSH.

Written in Rust. Open source, under the MIT license.

Configuration files and environment variables for local use and CI. A shared GitHub Action is planned.

In development. The CLI currently supports help and version output. Backup and restore commands are not available yet.

Getting started+

With repository access and Rust installed, build the current CLI: 

cargo build --locked --release
./target/release/svalbard --help
./target/release/svalbard --version

The repository is private during initial development.

Configuration & secretsPlanned+

Configuration files for backup jobs, environment variables for credentials, and documented precedence. The format is still being designed.

Database adaptersPlanned+

PostgreSQL and MySQL, using their native dump tools. MySQL support starts with InnoDB.

Backups will use one worker by default, with deadlines and contention checks. PostgreSQL snapshots can conflict with schema changes. Prefer replicas; backups cannot guarantee zero impact.

The database snapshot must close before upload begins.

Storage adaptersPlanned+

Amazon S3, Cloudflare R2, and SSH servers using SFTP or SCP. New destinations can be added through separate adapters.

Partial uploads must never be reported as successful backups.

CI & GitHub ActionsPlanned+

Run the CLI directly or use a shared, versioned GitHub Action. Both will accept secrets from the CI environment.

Noninteractive commands, machine-readable output, and documented exit codes.

RestoreLater+

A restore command follows the backup release. Before that release, real backup files must pass restore tests with the database’s own tools.

Why Svalbard?

Svalbard is the Arctic archipelago that houses the Global Seed Vault. The vault stores backup copies of seeds from collections around the world. That backup role is where the project’s name comes from.
